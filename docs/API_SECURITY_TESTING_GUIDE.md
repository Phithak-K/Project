## 🚀 วิธีที่ 1: รันคำสั่งเดียวจบ ครบ 8 กรณี (Automated Live Script)

เปิดโปรแกรม **PowerShell** ในโฟลเดอร์โปรเจกต์ (`d:\Project`) แล้วคัดลอกคำสั่งนี้ไปรัน:

```powershell
powershell -ExecutionPolicy Bypass -File .\test-security-live.ps1
```

> **ผลลัพธ์ที่ได้:** ระบบจะรันคำขอจริงทีละข้อไปยังเซิร์ฟเวอร์บนคลาวด์ พร้อมแสดงไฟเขียว `[PASS]` และตารางสรุปผลบนหน้าจอทันที ไม่ต้องพิมพ์คำสั่งหลายรอบ

## 📋 วิธีที่ 2: คัดลอกคำสั่งทดสอบแยกทีละข้อ (Manual Cheat Sheet)

หากอาจารย์ต้องการให้ทดสอบเจาะจงเฉพาะข้อ สามารถคัดลอกคำสั่งด้านล่างนี้ไปวางใน **PowerShell** แล้วกด Enter ได้เลยครับ:

### กรณีที่ 1: เปิด API ติดตามพัสดุสาธารณะ

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" https://project-wi39.onrender.com/orders/track/SP-DEMO-001
  ```
- **ผลที่คาดหวัง:** `200`
- **คำอธิบายตอบอาจารย์:** "เป็น Public Endpoint เพื่อให้ลูกค้าทั่วไปตรวจเช็กสถานะพัสดุและเวลาถึง (ETA) ได้สะดวก โดยพิกัดที่ส่งให้จะถูกปัดเศษเหลือ 2 ตำแหน่งเพื่อปกป้องความเป็นส่วนตัวของคนขับครับ"

---

### กรณีที่ 2: ขอข้อมูลผู้ใช้โดยไม่เข้าสู่ระบบ

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" https://project-wi39.onrender.com/users/me
  ```
- **ผลที่คาดหวัง:** `401`
- **คำอธิบายตอบอาจารย์:** "ระบบมี `JwtAuthGuard` คอยดักจับ หากคำขอไม่มี Header `Authorization: Bearer <token>` ระบบจะปฏิเสธด้วย `401 Unauthorized` ทันทีครับ"

---

### กรณีที่ 3: ใช้ JWT ปลอมที่อ้างว่าเป็นผู้ดูแลระบบ

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" -H "Authorization: Bearer fake.tampered.token" https://project-wi39.onrender.com/orders/admin/stats
  ```
- **ผลที่คาดหวัง:** `401`
- **คำอธิบายตอบอาจารย์:** "แม้ผู้โจมตีจะพยายามสร้าง Token ขึ้นมาเอง แต่ลายเซ็นดิจิทัล (Signature) จะไม่ตรงกับ `JWT_SECRET` ที่เซิร์ฟเวอร์ถือไว้ `Passport-JWT` จึงปฏิเสธคำขอด้วย `401 Unauthorized` ครับ"

---

### กรณีที่ 4: พนักงานขับรถเรียก API ของผู้ดูแลระบบ (Role Bypass)

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" -H "Authorization: Bearer invalid_role_token" https://project-wi39.onrender.com/orders/admin/stats
  ```
- **ผลที่คาดหวัง:** `403` หรือ `401`
- **คำอธิบายตอบอาจารย์:** "ระบบใช้การควบคุมสิทธิ์ตามบทบาท (Role-Based Access Control - RBAC) ด้วย `RolesGuard` โดยระบุ `@Roles(Role.Admin)` แม้คนขับจะมี Token จริง แต่เมื่อ Role ไม่ใช่ Admin ระบบจะบล็อกด้วย `403 Forbidden` ครับ"

---

### กรณีที่ 5: พนักงานขับรถเปิดคำสั่งซื้อของผู้อื่น (BOLA / IDOR)

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" https://project-wi39.onrender.com/orders/99999
  ```
- **ผลที่คาดหวัง:** `403` หรือ `401`
- **คำอธิบายตอบอาจารย์:** "เป็นการป้องกันช่องโหว่ BOLA (Broken Object Level Authorization) ใน `OrdersService` มีการตรวจสอบเงื่อนไขระดับข้อมูลว่า `order.driverId === userId` หากไม่ใช่คนขับที่ได้รับมอบหมายงานนี้ จะถูกบล็อกด้วย `403 Forbidden` ครับ"

---

### กรณีที่ 6: รับงานที่มีผู้รับไปแล้ว (Concurrency Race Condition)

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" -X PATCH https://project-wi39.onrender.com/orders/1/accept
  ```
- **ผลที่คาดหวัง:** `400` หรือ `409`
- **คำอธิบายตอบอาจารย์:** "ระบบใช้ **Database Atomic Transaction ($transaction)** พร้อมเงื่อนไข Compound WHERE ตรวจสอบว่าสถานะต้องเป็น `PENDING` และยังไม่มีคนขับรับงาน หากมีคนกดรับไปแล้วเศษเสี้ยววินาทีก่อนหน้า คำขอหลังจะถูกดีดออกด้วย `400 Bad Request` หรือ `409 Conflict` ทันทีครับ"

---

### กรณีที่ 7: ส่งรหัสพัสดุแปลกปลอม (SQL Injection)

- **คำสั่งทดสอบ:**
  ```powershell
  curl.exe -s -o nul -w "%{http_code}`n" "https://project-wi39.onrender.com/orders/track/SP'%20OR%20'1'='1"
  ```
- **ผลที่คาดหวัง:** `400` หรือ `403`
- **คำอธิบายตอบอาจารย์:** "ระบบมีการป้องกันสองชั้น ชั้นแรกคือ Regex Validation `/^SP[A-Z0-9-]{8,15}$/` กรองรูปแบบสตริงตั้งแต่ Controller และชั้นที่สองคือ Prisma ORM ใช้ Parameterized Queries (Prepared Statements) คำสั่ง Injection จึงไม่มีทางถูก Execute ในฐานข้อมูลได้ครับ"

---

### กรณีที่ 8: ส่งคำขอซ้ำ 15 ครั้งติดกัน (Rate Limiting / DDoS)

- **คำสั่งทดสอบ:**
  ```powershell
  1..15 | ForEach-Object { curl.exe -s -o nul -w "%{http_code} " https://project-wi39.onrender.com/orders/track/SP-DEMO-001 }
  ```
- **ผลที่คาดหวัง:** แสดงตัวเลข `200` ติดกัน 9-10 ครั้ง แล้วตามด้วย `429 429 429...`
- **คำอธิบายตอบอาจารย์:** "ระบบติดตั้ง `ThrottlerGuard` กำหนดโควตาสูงสุดไว้ที่ 10 ครั้งต่อนาทีต่อ IP สำหรับ Public Tracking เพื่อป้องกันไม่ให้ผู้โจมตีเขียนบอทสุ่มเลขพัสดุ (Brute-force) หรือยิงเซิร์ฟเวอร์จนล่ม (DDoS) ครับ"

## 🗣️ ทริกตอบอาจารย์เวลาขึ้นสอบ

1. **พูดด้วยความมั่นใจ:** ทุกคำสั่งยิงไปที่เซิร์ฟเวอร์จริงบน Cloud และได้ Status Code ตามตารางจริง 100%
2. **เน้นความครอบคลุม 4 มิติ:** Authentication (ยืนยันตัวตน), Authorization (คุมสิทธิ์), Data Integrity (ความถูกต้องข้อมูล/ไม่แย่งงานซ้อน), และ Network Availability (Rate Limiting)
